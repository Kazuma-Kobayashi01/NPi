# Model picker: recently used (#11)

The picker's `recently used` group is omp's own MRU, not desktop state: omp upserts `model_usage (model_key, last_used_at)` in `<agent dir>/agent.db` on every model switch (`set_model`, `cycle_model`, retry/advisor fallbacks — *not* per turn), and its terminal model selector orders by the same table. `src-tauri/src/model_usage.rs` reads it with `rusqlite` (`bundled`) behind the `model_usage_list` command; `CommandBridge` refetches via `OMP_BRIDGE.recentModels()` each time the models view opens and intersects the keys with the tab's models through `pickRecentModels` (`adapter.js`, regression `test-recent-models.mjs`; keys are `provider/modelId`, so the same id under two providers stays two models).

- The database path follows the tab's profile through `profiles::agent_dir_for` (`~/.omp/agent/agent.db`, `~/.omp/profiles/<id>/agent/agent.db`, `PI_CODING_AGENT_DIR` for the built-in profile only — all three verified against the installed omp).
- `CommandBridge` fetches the keys **for** its `profileId` prop (app-live's `activeProfileId`), passed explicitly to `recentModels(profile)`, tags them with it, shows them only while that tag still matches, and refetches on a profile change while open (tab switch, `switchSessionProfile` respawn); a response for a profile left meanwhile is dropped. Don't let the request fall back to `_activeProfileId()`: during a respawn's detach `activeSessionId` is null, so it resolves to the startup profile and would put that profile's list under the new tag. An unlisted id is refused by `resolve_owned` and yields no group.
- omp runs it in WAL mode. Open **read-only**, never `immutable=1` (that skips the WAL and reads stale pages), with a short `busy_timeout`, and **one connection per query** — a held read transaction pins the WAL and stalls omp's checkpoints. Never `SQLITE_OPEN_CREATE`: a missing database is a fresh profile.
- It is omp's private schema, not RPC. Any failure reads as an empty list, which leaves the plain model list — never an error in the UI.

## Floating model menu

`src/design/model-menu.jsx` is shared by the conversation composer, the welcome page and SideChat. It is a card after LabBot's picker (`labserver-dashboard/mac/LabBot/Sources/LabBot/ModelPicker.swift`), opaque in the theme's surface colours and one narrow column (360px, the viewport minus 24px at most; its horizontal position is corrected on open and resize, so upward and downward menus stay on screen).

The button reads "Model  Level ⌄". The card (`_MMCard`) shows the level in large type, coloured per level (`.mm-card[data-lv]`), the model's name under it with a chevron, and a stepped slider. The model's deepest level, when it has at least three, is named "Ultra" (`OMP_MODELS.effortStops(...).ultra`) in a violet gradient, on the card and the button; the slider's fill then flows and sparks drift through it (CSS only, off under `prefers-reduced-motion`). A click on the model name opens the model list: the favourite/MRU models with their vendor tag, the current one ticked and the others numbered, then More models › vendors › that vendor's models, and Manage models…. The digit keys 1-9 pick from that list in either view, so the card needs no list open for them; Escape steps back to the card, then closes.

The slider is a native range input over the drawn capsule: one stop per level `loadLevels` returned for the current model, in omp's order; `OMP_MODELS.effortStops` / `levelLabel` (`app/model-pick.js`, `test-model-pick.mjs`) place the thumb and name the levels. A drag shows its level and sends `onSetLevel` once, on release (pointer, key or blur); a click on the stop in use sends it too, which pins a level `auto` resolved to. The menu stays open, and the thumb stays where it was dropped until the level prop changes (omp may clamp it), or for 1.5 s when it does not. A level omp did not list (`auto` before it resolves) has no stop: a hollow knob at the start and no fill. A model with fewer than two levels has no slider. The levels are fetched when the current model changes (so the button can say "Ultra" with the menu closed) and on every open.

The model ordering, `provider/id` identity, numeric shortcuts, native Tab order and Escape behavior are unchanged. This floating menu remains separate from `CommandBridge`'s searchable model view.
