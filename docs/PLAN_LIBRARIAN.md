# Librarian 方案(Academic 参考文献库)

参考 EndNote 的思路,在 Academic 项目里做一个本地参考文献库。本文是**规划,不代表已实现,也不代表已授权实施**;其中提到的第三方库均未试用,需要在对应阶段先做小验证。

## 1. 已确定的决定

- **库放在项目里**:每个 Academic 项目一个库,不做跨项目共享库(以后再议,先提供"把条目复制到另一个项目")。理由:与 Copilot 的项目级授权一致,避免项目间泄露。
- **元数据在线查询只在用户点击时进行**:不后台联网,不自动补全。
- **不做 Word 引用**:不做 Office 插件,不读 EndNote 专有的 `.enl` 库;互通靠 RIS / BibTeX / CSL-JSON。

## 2. 目标与边界

**目标**:题录管理、导入导出、查重、引用格式化,并让 Copilot 凭库里的真实条目回答和核对引用,抗幻觉。

**不做**:Word 插件、EndNote 库直读、云同步和多人协作、PDF 阅读与批注(以后)、后台自动联网。

## 3. 数据模型

- 标准格式用 **CSL-JSON**:每条参考文献存一份 CSL-JSON,再加几列可索引字段(`citekey`、标题、第一作者、年份、DOI、类型、添加时间)。这样格式化引擎和导入导出可以直接使用。
- 库存放在项目的 `research.db`(与 `docs/PLAN_3.0.md` 里的检索库为同一个数据库)。
- 表:
  - `references`:`id`、`citekey`(项目内唯一)、`csl_json`、索引字段、`source`(`manual / ris / bibtex / pdf / online`)、`created_at`、`updated_at`。
  - `groups`:手动分组;`group_refs`:条目与分组的多对多。
  - `tags`、`ref_tags`。
  - `attachments`:`ref_id`、项目内相对路径、内容哈希、类型(`pdf / note / other`)。
  - `notes`:每条参考文献的笔记(也可对应 `notes/` 下的文件)。
  - `change_log`:用户确认过的写入记录,便于撤销。
- **PDF 仍在 `papers/`,原文只读**:导入时复制为新文件,按 `<年份>-<第一作者>-<短标题>` 命名,不改动用户的原文件;库里只记相对路径和哈希。
- 用户成果(条目、分组、笔记)不是可重建缓存;只有 FTS 索引可重建。

## 4. 功能分层

### 4.1 L0:数据层

- Rust 模块 `librarian/`(`store`、`import`、`export`、`dedupe`)与类型化命令;前端只传 `projectId`、`refId`、`groupId`,不传 SQL 或任意路径。
- 导入:RIS、BibTeX/BibLaTeX、CSL-JSON。RIS 格式简单,可自写或用现成库;BibTeX 用现成解析库(候选 `biblatex`),先做小验证。
- 导出:`.bib`、`.ris`、CSL-JSON。
- 查重:DOI 精确匹配;规范化标题加年份加第一作者的模糊匹配;重复项由用户确认合并,不自动合并。
- `citekey` 生成规则:`<第一作者小写><年份><标题首词>`,冲突时加后缀。

### 4.2 L1:Librarian 标签页

- Academic 里加一个应用级标签页"Librarian",三栏:左边分组与标签,中间列表(列:作者、年份、标题、期刊、附件、标签)加搜索,右边详情(元数据表单、附件、笔记)。
- 手动新增、编辑、删除条目;删除进入项目回收区,不做永久删除。
- 搜索先用 SQLite FTS5,中文用 `docs/PLAN_3.0.md` 里已验证的 unigram + bigram 规范化方案。

### 4.3 L2:引用格式化

- 用 CSL 样式引擎;候选 `hayagriva`(Rust),**需先验证**中文样式(GB/T 7714)和 CJK 细节是否可用,不行再评估其他方案。
- **样式覆盖面对标 EndNote**:EndNote 自带数千种输出样式(`.ens`,专有格式)。CSL 生态有约一万种样式(IEEE、APA、Chicago、MLA、Nature、Vancouver、Harvard、GB/T 7714 及各期刊样式),格式开放,覆盖面不输 EndNote,因此不用做 `.ens` 兼容。
  - 随包带一批常用样式(首批:APA 7、IEEE、Chicago、MLA、Nature、Vancouver、Harvard、GB/T 7714),并配套 CSL 区域文件(zh-CN、zh-TW、en-US、ja-JP)。
  - **用户可自行添加 `.csl` 文件**:放入应用的样式文件夹或在界面里导入,导入时校验为合法 CSL,不执行任何脚本;添加后出现在样式下拉里,并可设为项目默认样式。
  - 样式下拉支持搜索;"在线获取更多样式"如要做,也只能是用户点击后从 CSL 官方样式库下载单个文件,并预览后确认,放到 L3 的联网规则里。
  - CSL 样式文件为 CC-BY-SA,随包时保留署名并在文档里写明。
- **导入导出格式也对标常用的**:除 RIS、BibTeX、CSL-JSON 外,后续按需加 EndNote XML(导出文件,不是 `.enl` 库)、PubMed/MEDLINE(`.nbib`)、Web of Science 纯文本导出;每种格式一个独立解析器,各带样例文件测试。
- 功能:复制单条引用、复制所选条目的参考文献列表(纯文本和富文本)、选择输出样式。
- 写作:Markdown 草稿使用 `[@citekey]`,Librarian 可对草稿生成参考文献列表和行内引用;LaTeX 用导出的 `.bib`。

### 4.4 L3:PDF 导入与元数据

- **前置:PDF 文本提取**。应用目前没有 PDF 文字提取,它同时卡住"PDF 检索"和这一层。可选路线,需各做一次小验证后再定:
  1. 用应用自带的 Python 运行时(固定版本、离线安装)装 PyMuPDF 之类;
  2. 用 Rust 的 PDF 库。
  
  比较维度:体积、中文与双栏版面、表格、速度、许可。
- 流程:拖入或选择 PDF → 提取首页文字 → 本地规则找 DOI、标题、作者 → 预填一条草稿条目 → **用户确认后才入库**。
- **在线查询由用户点击触发**:条目详情里的按钮"从 DOI 或标题查询元数据"。由 Rust 发起请求,只允许固定的元数据服务域名(候选:Crossref、OpenAlex),只发送 DOI 或标题,不发送 PDF 内容;结果以差异形式预览,用户逐字段确认后才写入。无网络或失败时,保持本地草稿,不影响使用。
- 无 DOI 的论文:可选"让模型从首页文字提取元数据"。会把首页文字发给所选模型服务商,需在界面上明示并由用户点击。

### 4.5 L4:AI Librarian

- 给 Copilot 增加库工具(固定、由 Rust 执行、项目级授权):`library_search`、`library_get`(读条目与引用格式)、`library_suggest`(提出标签、分组、补全建议,只生成建议)。主聊天里的 Agent 只读。
- **引用核对**:给一份草稿,逐条核对其中引用是否在库中、作者与年份是否匹配、有无库里不存在的条目,标出疑似编造的引用。确定性核对由 Rust 完成;语义判断只作标注。
- 标签和分类建议:先给建议,用户确认才写入。
- 任何写入库的操作都经"建议 → 用户确认 → Rust 执行"。

## 5. 与现有架构的关系

- 复用:`research.db` 与 FTS5 计划、Host Tool RPC、`copilot.rs` 的路径安全和项目授权、`academic_space.rs` 的项目脚手架。
- 项目脚手架增加 `library/` 说明,并在 `.omp/skills/` 里加一个 Librarian 技能;`.omp/RULES.md` 增加"不得编造引用"之外的规则:库内条目才可作为引用来源。
- 权限:前端不能注册工具;库命令由 Rust 校验项目归属;主聊天只读,Copilot 可建议、写入需确认。
- 网络:只有用户点击的元数据查询出网,域名白名单、只发 DOI 或标题;其余保持"封闭隐式出网"。

## 6. 阶段与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| L0 | 数据层、导入导出、查重、命令与测试 | 导入导出往返无损;重复项被识别;重启后数据不丢;项目间互不可见 |
| L1 | Librarian 标签页 | 能手动管理条目、分组、标签并搜索;中文短词可搜到 |
| L2 | 引用格式化 | 6 种样式输出与参考样例一致,GB/T 7714 的中文条目可用 |
| L3 | PDF 导入与元数据 | PDF 预填草稿正确率可测;在线查询只在点击后发生;断网时功能不退化 |
| L4 | AI Librarian | 引用核对能抓出库外条目;库写入都经用户确认;越权与路径逃逸用例失败 |

建议顺序:**L0、L1、L2 先做**,得到一个不含 PDF 的参考文献管理核心,可独立使用;PDF 文本提取的小验证与 L2 并行,为 L3、L4 铺路。

## 7. 风险与待验证项

| 风险 | 应对 |
|---|---|
| PDF 文本提取方案未定 | 作为独立前置,做小验证后再选;未解决前 L3、L4 只做不依赖 PDF 的部分 |
| `hayagriva` 的中文样式支持程度未知 | L2 开始前先做小验证;不行就换引擎或缩小样式范围 |
| CSL 样式许可(CC-BY-SA) | 随包保留署名,文档说明 |
| 元数据来源出错(同名论文、错误 DOI) | 在线结果只作预览,逐字段确认;保留来源标记 |
| 模型从首页提取元数据可能出错或遗漏 | 明示"模型提取",与"已核对"区分;确定性核对不依赖模型 |
| 查重误合并 | 只提示、不自动合并 |
| 条目与 PDF 对不上(文件被移动) | 用哈希重新定位,找不到时标为"附件缺失",不静默清除 |
| 项目库损坏或迁移失败 | `research.db` 带 schema 版本与迁移,迁移前备份 |

## 8. 不在本期范围

Word 引用与 EndNote 库直读、跨项目共享库、PDF 阅读与批注、云同步与协作、后台自动补全元数据。
