# CLI 维护计划

CLI 缺陷与维护任务单独记录在此；[Academic 模式计划](../PLAN.md) 保持原有范围。

## CLI-001：修复 Ctrl+C 会话中断问题

- 状态：修复已合并且用户手动测试通过；发布版本为 `1.0.1-hotfix01`。
- 来源：用户反馈 CLI 中使用 Ctrl+C 中断会话存在问题。
- 范围：CLI 的 Ctrl+C 输入处理、当前轮次取消，以及中断后的会话恢复能力。
- 已复现：CLI 运行长时间 shell 命令时，Ctrl+C 仅清空输入，命令未取消，后续命令无法执行。用户未进一步描述的其他中断症状不视为已覆盖。

### 执行步骤

1. 读取 `omp/AGENTS.md`，检查现有快捷键和中断语义；结合用户的具体故障表现，在隔离 CLI 会话中复现并保留证据，不对正在使用的会话发送中断信号。
2. 沿 Ctrl+C 按键处理、取消信号和会话状态收尾定位根因；区分当前轮次取消、工具执行取消与退出 CLI，避免把不同语义混为一谈。
3. 修复已确认的根因，沿用现有取消和资源清理机制；不以吞掉异常、强制退出或无条件杀进程替代正确收尾。
4. 为确认的故障保留回归用例，并在真实交互式 CLI / PTY 中验证修复前后表现；同步相关文档与 changelog。

### 验收检查

- 用户报告的具体故障在修复前可复现，修复后不再出现。
- 应当取消当前轮次的场景中，Ctrl+C 能结束该轮处理并恢复可输入状态，下一条消息可以正常执行。
- 中断后的消息历史和会话状态一致，重新打开会话不会丢失已保存的内容或残留错误的运行状态。
- 若复现涉及流式生成、工具执行或重复按键，分别验证其取消、资源清理和退出行为，不改变无关快捷键语义。
- 不影响当前 CLI / GUI 真实会话；涉及 Rust 时仅使用 DevStore 管理的 `rust/current` 环境。

### 修复记录

- 修复分支：`hotfix/cli-ctrl-c`；已快进合并到根仓库 `main` 和内核仓库 `npi`，内核修复提交为 `d099767964`。
- 修改：主会话运行中，Ctrl+C 复用 Esc 的取消与队列恢复逻辑，不再触发清空或双击退出；空闲和退出阶段保留原有行为。
- 回归：增加一条队列恢复与误退出保护用例；修复前失败，修复后通过。
- 真实 CLI / PTY：临时 HOME、临时工作目录、`--no-session`，运行 shell 长命令后发送 Ctrl+C，再执行后续命令。修复前后续命令无法执行；修复后取消成功、CLI 存活且后续命令成功。
- 修复验证阶段未跑全量测试、未发送真实模型请求，未替换已安装应用或随包内核。
- 最小检查结果：Ctrl+C 定向回归 3 项通过，紧急退出回归 1 项通过；两个修改的 TypeScript 文件通过 oxlint 与 oxfmt 检查。
- 开发交付：使用项目本地 Bun 执行内核包的 `bun run build`；开发产物的 ad-hoc 签名校验与隔离 CLI / PTY Ctrl+C 冒烟通过，随后用户确认手动测试通过。
- 发布来源：`1.0.1-hotfix01` 内核提交为 `d5c52f14e0`。内核仓库指向上游，不向其推送；Release 附完整内核源码快照，根仓库的自动源码归档不包含 `omp/`。
