# Virtual Office GUI 计划

状态：**已实施，未编译进 app、未在真实应用中运行**（2026-11-10 起草并实施）。实现说明见 `desktop/docs/architecture/office-window.md`；与本计划的出入见第 8 节。内核功能见 `omp/docs/virtual-office.md`（内核提交 `b2b2cc04fd`）。本文只定方案与分工，不代表已授权实施。

## 1. 目标

为 Virtual Office 做一个**独立的 OS 窗口**：

- 有自己的窗口和数据连接，不依附主窗口当前的标签页。
- 主窗口隐藏到菜单栏时它照常运行，可以单独放在另一块屏幕上。

窗口内有两层页面：

- **总览页**（窗口打开即见）：
  - 上方是公司总状态：像加油机一样实时跳动的 Token 用量和金额（同时显示 USD 与 JPY）、公司信息、进度。
  - 下方每个 Office 一张卡片：成员组成、各人的 Token 与金额。
- **详情页**：点开某张卡片后，在同一个窗口里覆盖出来，不再开新的 OS 窗口。页面分 N 列（N = 该 Office 的成员数，3–6），每列**只读**显示一名成员的对话。

Office 在 Desktop 里**按标签页单独开启**：只有打开了 Office 的 Code 标签页才是总经理。

不做：

- 不把设置窗口化。
- 不做手机远程。
- 不在 GUI 里看代码差异（PR 的改动先看文件列表与行数，完整 diff 留到以后，可接 Git 浏览器）。
- 不在 GUI 里干预成员：不发消息、不停止。要中止工作，在总经理的对话里处理。

> "独立窗口"与现有"二级窗口"的区别：历史、审批、Plan、Git 浏览器这些二级窗口（`panel-windows.md`）是靠主窗口推送快照、转发调用来工作的，主窗口不在它们就不能用。Office 窗口自己订阅内核数据，主窗口不参与。

### 2.1 总览页

**加油机计量器**（顶栏左侧）

- 三组大数字：
  - **金额**：USD 和 JPY 并列显示。JPY 由 USD 按联网获取的汇率换算，显示为整数日元。
  - **Token 量**：输入 + 输出 + 缓存写入，与内核 `progress.tokens` 口径一致，不含缓存读取。
  - **单价**：金额 ÷ Token，折算为每百万 Token 的加权单价，同样显示 USD / JPY。
- 运行中数字滚轮式跳动：两次进度帧之间做插值，看起来连续上涨。旁边有"加油中"指示灯脉动，全部空闲时数字定格、指示灯熄灭。
- 统计范围两档，默认"今日"：
  - **今日**：从本机当天 00:00 起算（日本时间），跨过午夜自动归零重新累计。
  - **累计**：该项目开启 Office 以来的总和。
  - 两档都来自内核的按天用量账本（见第 4 节 K2）。
- 金额标注"按模型目录价估算"：订阅制登录（OAuth）的实际花费不是这个数。
- 汇率显示在计量器旁，带汇率日期。
- 计量器下方一条构成条：总经理与各 Office 各占多少。

**汇率**

- 由 Rust 端联网获取，不从网页发请求，保持现有严格 CSP 不变。
- 数据源：Frankfurter（欧洲央行每日参考汇率，免密钥），只请求 `USD→JPY` 一个币对，不发送任何用户数据。
- 缓存在 `<app cache>/fx.json`（汇率和日期）。打开 Office 窗口时，缓存超过一天才重新获取。
- 获取失败时沿用上次缓存，并把汇率日期标黄。从未成功获取过时，JPY 显示"—"并提示汇率不可用，USD 照常显示。

**公司信息**

- 仓库名与基准分支。
- 规模（Team / Studio / Enterprise）、Office 数、成员总数。
- 总经理所在标签页及其在线状态。

**进度**

- 按 PR 流水线排成漏斗：派工中 → Worker PR 待审 → Office PR 待审 → **待你合并** → 已合并。
- "待你合并"不为零时高亮，并带合并入口。

**Office 卡片**

- 网格随规模自适应：1 个时一张宽卡；3 个时一行三张；6 个时 3×2。
- 标题：Office 编号 + 阶段徽章（空闲 / 工作中 / 审核中 / 等总经理审 / 等你合并）。
- 成员行：Leader 置顶（★）。每行显示名字、能力（普通 / 专业 / 专家三种颜色）、模型、状态灯（运行中 / 空闲 / 失败），以及本人今日的 Token 与金额。
- 底部依次是：
  - Office 小计（Token、USD、JPY）
  - 当前任务一句话（截取 Leader 收到的派工）
  - 未完成 PR 数
  - 记住的经验条数
- 工作中的卡片带流光边框，复用现有流光样式。
- 点击卡片进入详情页。

### 2.2 详情页（N 列成员对话，只读）

- 在 Office 窗口内全屏覆盖。按 Esc 或点"返回"回到总览。
- **顶栏**：Office 编号、阶段、本 Office 的小计计量器（与总览同一组件的紧凑版），以及该 Office 的 PR 列表（可折叠，每条显示状态与审核意见）。
- **列**：
  - 每名成员一列，Leader 在最左，列宽均分。
  - 每列最窄 320px，窗口放不下时整页横向滚动。
- **列头**：名字、角色、能力、模型、状态、今日 Token 与金额、上下文占用条。
- **列体**：该成员的对话流。
  - 每次派工为一段：段首写明任务及派工人（总经理或 Leader），段尾写明结果和提交的 PR 编号。
  - 消息渲染复用聊天组件的紧凑模式：助手文本照常显示，思考和工具卡默认折叠。
  - 运行中自动跟随到底部；手动往上滚后暂停跟随，出现"回到最新"按钮。
- **历史**：本次会话之前的派工，从内核账本记录的会话文件读取（见 K2），可以按段展开。
- **只读**：没有输入框，也没有停止按钮。不复用 `subagent-controls.jsx`。

### 2.3 所有者操作

- **合并 / 退回**：总经理批准后，Office PR 在卡片和顶栏的"待你合并"处出现"合并到 <分支>"按钮。
  - 合并：先二次确认（显示标题、文件数、增删行数），再发 `office_command ["merge", n]`。
  - 退回：必须填写原因，发 `["reject", n, 原因]`。
  - 内核拒绝时（目标分支已改动同一处、有暂存改动等），原样显示内核给的原因。
- **名册抽屉**：在窗口右上角。可以：
  - 切换规模、设置每个 Office 的人数
  - 添加 / 移除成员
  - 设置模型（复用 `model-menu.jsx` 的模型选择器）、能力
  - 改任 Leader

  全部经 `office_command` 执行，不另写一套规则；内核报错原样显示。名册是全局共用的，各标签页的 Office 用同一份。
- **记忆**：卡片上点"记得 N 条经验"展开查看，可删除整个 Office 的记忆（`forget`，需确认）。

### 2.4 按标签页开启 Office

- 开关放在**主窗口的标签页上**，不在 Office 窗口里。位置在标签页头部的 Office 按钮旁边（或标签页右键菜单），只对 git 仓库里的 Code 标签页显示。
- 开启后：该标签页的主对话变成总经理，并出现"打开 Office 窗口"的入口。
- 关闭后：该标签页恢复普通对话。已开着的 Office 窗口转为离线状态。
- 状态随标签页保存在 `open-tabs.json`，重开应用、恢复标签页时保持。
- 新建标签页默认关闭。
- 切换开关不重启内核：由内核在当前会话里重新装配 `office` 工具和总经理提示词（见 K6）。

## 3. 桌面端架构

### 3.1 窗口

- **新窗口种类**：不并入 `panel_window.rs` 的 `KINDS`（那是依附主窗口的二级窗口）。新增 `src-tauri/src/office_window.rs`。
  - 窗口标签为 `office-<仓库根路径 + 基准分支 的哈希>`，一个公司一个窗口，重复打开时只把已有窗口带到前台。
  - 页面地址为 `index.html?office=<id>`，`navigation_guard.rs` 只让 `office-` 窗口加载这种页面。
  - `capabilities/default.json` 的窗口列表加上 `office-*`。
- **生命周期**：
  - 主窗口按 Cmd+W 只是隐藏，Office 窗口不受影响。
  - Office 窗口自己按 Cmd+W 才关闭。
  - 窗口位置与大小写入 `ui_state` 并在下次打开时恢复。这是新做的，现有二级窗口都不记位置。
- **打开入口**：
  - 标签页头部的 Office 按钮：仅在该标签页已开启 Office 时显示。
  - 菜单栏 Window → Office。
  - 快捷键 **Cmd+Shift+O**（其他平台 Ctrl+Shift+O）：打开当前标签页对应公司的 Office 窗口。在 `app/keymap.js` 登记为 `desktop.office.open`，默认键位 `["ctrl+shift+o", "shift+super+o"]`（已核对未被占用），可在快捷键设置里改。当前标签页没开 Office 时，按下只提示"这个标签页没有开启 Office"。

### 3.2 数据链路

Office 窗口不走 `panel-link` 那套快照转发，直接连总经理所在标签页的内核进程：

- **接收**：监听 `agent://line/<sid>`（Rust 的 `reader.rs` 已用 `app.emit` 广播给所有窗口）。窗口打开时先用 `replay_events` 补上之前的数据。
- **发送**：通过 `send_command` 发给同一个会话，请求 id 一律加 `office:` 前缀。
- **新模块**（遵守无打包、按 `index.html` 脚本顺序加载、IIFE 全局变量的约定）：
  - `src/app/office-live.js`：单会话桥，负责监听、发送、按 id 对应响应、发现内核退出。不复用 `live.js`，因为它管理多标签页，太重。
  - `src/app/office-model.js`：纯 reducer。把 `OfficeState`、子代理帧和会话统计合成视图模型：各成员 / Office / 公司的小计、阶段、PR 漏斗、计量器的目标值。配回归测试。
  - `src/app/office-meter.js`：计量器的纯逻辑，包括插值、数字格式、USD→JPY 换算、"今日"的 00:00 边界与跨午夜归零。配回归测试。
  - `src-tauri/src/fx_rate.rs`：汇率获取与缓存（第 2.1 节"汇率"），暴露一个 `fx_rate_usd_jpy` 命令，返回汇率、日期和是否过期。
  - `src/design/office/`：`office-window.jsx`、`meter.jsx`、`office-card.jsx`、`member-row.jsx`、`office-detail.jsx`、`member-column.jsx`、`roster-drawer.jsx`、`merge-dialog.jsx`。
  - 样式放在 `src/design/layout/office.css`，并登记进 `_index.css`。

**数据来源对照**

| 显示内容 | 来源 |
|---|---|
| 名册、规模、PR、记忆 | `get_office_state`，加上内核主动推送（K1） |
| 今日 / 累计用量（含总经理） | `OfficeState` 中的按天账本汇总（K2） |
| 运行中成员的实时增量、状态、上下文 | `subagent_progress` 帧：`agent` 字段就是成员名，按名册对应到 Office；任何嵌套深度的成员都能收到。在 K2 汇总值之上叠加，下一次推送到来时以账本为准 |
| 总经理的实时增量 | 主会话的 `message_end` 事件 |
| 成员实时对话 | `subagent_event`：只在详情页打开时订阅到 `events` 级（这一级开销大） |
| 成员历史对话 / 补齐 | `get_subagent_messages`（按会话文件和字节偏移增量读取） |
| 阶段、当前任务 | `OfficeState` 新字段（K3） |
| JPY 汇率 | `fx_rate_usd_jpy`（Rust，联网 + 缓存） |

### 3.3 必须先处理的共享问题

1. **订阅级别冲突**
   - 问题：`set_subagent_subscription` 是进程级的。主窗口切换标签页时会把被离开的会话降到 `progress` 或 `off`（`live.js` 的 `_switchToSession`），这会掐断 Office 窗口的实时数据。
   - 做法：在 Rust 端（`agent/`）加按会话的订阅仲裁。每个窗口登记自己需要的级别，实际发给内核的是所有登记中的最高级别。主窗口和 Office 窗口都改为登记，不再直接发命令。
2. **响应串台**
   - 问题：主窗口有些响应是按命令名处理的（例如 `live.js` 里处理 `get_session_stats` 的分支）。Office 窗口发同名命令时，结果会被主窗口当成自己的。
   - 做法：主窗口只处理自己发出的 id。实施前逐个检查 `live.js` 里按命令名分派的分支。
3. **命令白名单**：`agent/mod.rs` 的 `ALLOWED_COMMAND_TYPES` 加入 `get_office_state`、`office_command`、`set_office_enabled`，以后内核新增的命令也要加。
4. **总经理离线**
   - 情形：标签页关闭、该标签页关掉了 Office，或内核退出。
   - 表现：Office 窗口进入"离线"状态，顶部提示、数据冻结。
   - 离线时仍可读取名册、PR、记忆和用量：按 `omp_cli.rs` 的做法跑一次 `npi office --json`。
   - 提供"回到总经理标签页"按钮。
5. **同一公司多个总经理**
   - 问题：按标签页开启后，用户仍可能在同一仓库的两个标签页都打开 Office，两个总经理会共用工位（见 K4）。
   - 做法：窗口按公司（仓库 + 分支）打开，而不是按标签页。同一公司有多个在线总经理时，连接最近活动的那个，并在顶栏标明连的是哪个。开第二个时，在标签页上提示"这个仓库已有一个总经理"，但不禁止。

## 4. 内核前置工作（在 `omp` 里做，先于桌面端）

| 编号 | 内容 | 原因 |
|---|---|---|
| K1 | 名册、PR、记忆、用量变化时推送 `office_state` 帧（带完整 `OfficeState`） | 省掉轮询；合并、审核这类变化需要立刻反映到卡片上 |
| K2 | **按天用量账本** `npi-office/usage.json`：每次 `message_end` 把用量（输入、输出、缓存读写 Token，USD 金额）记入"本机日期 → 成员"的桶，总经理记在 `general-manager` 下；另记每次派工的运行记录（成员、会话文件、起止时间、关联 PR）。`OfficeState` 增加今日与累计汇总（按成员、Office、公司）和每名成员最近若干次运行 | "今日"必须按 00:00 精确切分，跨午夜的派工也要拆对，所以按消息记账，不能等派工结束才记；详情页历史也靠运行记录 |
| K3 | `OfficeState` 每个 Office 增加 `phase`（空闲 / 工作中 / 审核中 / 等总经理审 / 等你合并）和当前任务摘要 | 卡片阶段徽章要用；"工作中"由 K4 的工位锁判定 |
| K4 | 跨进程工位锁：把"一个工位一次一个任务"从进程内变量改为 `npi-office/` 下的锁文件 | 两个总经理会话可能同时往同一工位派活 |
| K5（可选） | 进度帧加入输入 / 输出拆分 | 计量器可以实时显示输入输出比例；不做的话，等 K2 推送到来时也能拿到拆分 |
| K6 | **按会话开启 Office**：`office.enabled` 对 RPC 宿主不再沿用全局设置（`protocolDefault: ["rpc"]`，默认关），新增 RPC 命令 `set_office_enabled { enabled }`，只在当前会话生效（运行时覆盖，不写配置文件）；内核随即重新装配 `office` 工具并重建总经理提示词。Desktop 恢复标签页时，按 `open-tabs.json` 记录的状态在会话就绪后发送此命令。CLI 的行为不变，仍由全局设置决定 | Desktop 改为每个标签页单独开启（第 7 节决定 2） |

每项都要配内核测试，改动线协议后重新生成（`gen:rpc`）。

## 5. 分阶段

**已完成（2026-11-10，内核提交 `9c8df457d7`）：CLI 的 `/office` 改成 TUI。** 面板在 `omp/packages/tui/src/overlays/office-panel.ts`，无参数的 `/office` 打开它，文字版状态改用 `/office status`。原要求如下：

- 只输入 `/office`（不带参数）时，打开全屏 TUI，交互方式和 `/settings` 界面一样：方向键移动、回车进入或确认、Esc 返回。
- 能调的内容：开关 Office、规模、各 Office 人数、成员的模型、能力与 Leader、添加 / 移除成员。还能查看 PR，并合并或退回待你处理的 Office PR，以及查看或清除 Office 记忆。
- 保留现有全部命令：`/office on`、`/office merge 4` 等带参数的写法照旧直接执行，`npi office …` 也不变。
- 所有改动仍经 `office/commands.ts` 的同一套逻辑执行，TUI 只是界面，不另写规则。
- 实施前先读 `/settings` 与 `/rank` 的全屏界面实现，沿用它们的组件和按键约定。

## 7. 已定的决定（2026-11-10）

1. **币种**：显示 USD 和 JPY，不显示 CNY。JPY 汇率由 Rust 端联网获取（Frankfurter / 欧洲央行），每天最多获取一次，失败时沿用缓存。
2. **Office 开关范围**：Desktop 中每个标签页单独开启，状态随标签页保存；CLI 仍用全局设置。需要内核 K6。
3. **成员对话只读**：详情页不能发消息，也不能停止成员。
4. **快捷键**：Cmd+Shift+O（其他平台 Ctrl+Shift+O），可在快捷键设置里改。
5. **统计周期**：按天，从本机当天 00:00 起算；只有"今日"和"累计"两档，不设清零按钮。

## 8. 实施结果与出入（2026-11-10）

- 内核 K1–K4、K6 已做（内核提交 `c3b34c2599` 及其后续提交）；K5 未做，输入/输出拆分不需要，计量器只用总量。
- **窗口种类**：没有新建 `office_window.rs`，而是作为 `panel_window.rs` 的 `office` 种类，按**标签页**开窗（窗口标签带会话 id），而不是按"仓库+分支"。原因：Office 已改为按标签页开启，窗口跟着总经理所在的标签页走最直接。同一仓库两个总经理的情形，每个窗口只显示自己标签页收到的推送。
- **Office 开关位置**：放在侧边栏导航的 Office 项和标签页右键菜单，而不是标签页头部。
- **订阅仲裁**已做（`agent/subscription.rs`），但 Office 窗口目前直接按字节偏移读成员的会话文件（运行中每 1.2 秒一次），不订阅 `events` 级帧，开销更小。
- **未做**：窗口位置记忆、"待你合并"系统通知、PR 差异查看。
- **已验证**：内核单元测试、离线模拟模型的端到端 RPC 试跑、桌面端 JS 回归与前端构建、相关 Rust 测试与 clippy、在浏览器里用假数据渲染并操作窗口。**未验证**：编译进 app 后的真实窗口。
