# CLI(终端界面)改版方案:参考 OpenCode 的 UI

**实施状态：阶段 1、2 已完成开发，待用户在真实终端确认效果；普通 CLI 的思考默认折叠也已实现。用户消息左竖线已做；回复尾行沿用已有的用量行（时间、Δ、token、ttft、tok/s，未含模式与模型）；右侧 Context 栏与会话标签条未做，状态行已显示上下文用量。**

目标:把 `npi` 的交互式终端界面(omp 的 TUI,在 `omp/` 独立仓库)改成 OpenCode 那种干净的"居中提示框 + 对话框 + 侧栏"风格。界面形态参考 OpenCode,标志与文案用 NPi 自己的,不复制它的 logo 和品牌字样。

## 1. 参考截图里的六个界面

| # | 界面 | 要点 |
|---|---|---|
| 1 | 首页 | 居中的像素 logo;其下一个居中提示框:左侧一条强调色竖线、填充底色、占位提示 `Ask anything… "…"`;框内底部一行 `模式 · 模型 提供商`;框外右对齐快捷键提示 `shift+tab agents  ctrl+p commands`;左下 `~`(目录),右下版本号 |
| 2 | 斜杠命令 | 输入 `/` 后在提示框上方弹出列表,每行 `/命令  说明`,选中行整行填充强调色 |
| 3 | 设置对话框 | 居中模态,标题 + 右上 `esc`;搜索框;按组(Appearance、Session)分段,组名用紫色;每行"名称 ←→ 右对齐的当前值",选中行填充;底部提示 `change ←/→` |
| 4 | 会话列表 | 标题 `Sessions for <用户>`;搜索;按日期分组;底部动作 `delete ctrl+d  rename ctrl+r  all projects ctrl+a` |
| 5 | 会话视图 | 顶部会话标签条(+ 新建);用户消息带左竖线;思考折叠成 `+ Thought · 136ms`;回复下一行 `模式 · 模型 · 耗时 · tok/s`;右侧栏:标题、Context(token 数、已用百分比);底部提示框;状态行 `10.1K (5%)  ctrl+p commands` |
| 6 | 连接服务 | 模态列表,分 Popular、Services 两段,带搜索 |

共同的视觉语言:**深色底、少量强调色(选中行橙、组名紫、模式蓝)、模态统一"标题 + esc、搜索、分组列表、底部动作栏"、所有可操作项旁边直接写出快捷键**。

## 2. omp 现状(已读代码的部分)

TUI 不是从零开始,而且已经很模块化:

- 提示框有可插拔的"形状"(`packages/tui/src/components/composer/`:`box`、`band`、`claude`、`pi`、`borderless`、`rule`、`field`、`rail`)。其中 **`rail` 已经是"左侧强调竖线 + 填充底色"**,和截图 1、5 的提示框同款;默认形状是 `band`(`prompt/composer.ts` 的 `COMPOSER_DEFAULTS`)。
- 首屏由 `prompt/welcome.ts`(`WelcomeComponent`)和 `modes/startup-composer.ts` 负责,首次运行还有一个设置向导(`packages/tui/src/setup/`)。
- 主体逻辑在 `modes/interactive-mode.ts`(约 9500 行)和 `modes/controllers/`(`selector-controller.ts` 管各种选择器,`command-controller.ts` 管斜杠命令,`input-controller.ts` 管输入)。
- 聊天消息在 `packages/tui/src/chat/`(用户消息、助手消息、思考、工具执行等),界面外壳在 `chrome/`、`overlays/`。
- 主题、符号集在 `packages/tui/src/theme`、`symbols.ts`。

**还没读、需要先摸清再动的部分**:对话框(选择器)现在怎么画、有没有统一的"列表模态"组件;状态栏(`status-line`);有没有侧栏的概念(截图 5 的右侧栏看起来是新东西);会话标签条是否存在。

## 3. 分阶段

**阶段 1:首页与提示框（已完成开发）**
- 默认形状改为 `rail`,并给它加上"框内底行:`模式 · 模型 提供商`"。
- 首页:logo + 居中提示框 + 右对齐快捷键提示 + 左下目录/右下版本;占位文案按模式变化。
- 验收:新装、没配置过的用户进入 `npi`,首屏与截图 1 同构;窄终端(80 列)不破版。

**阶段 2:统一的列表模态（已完成开发）**
- 抽一个"列表模态"组件:标题 + `esc`、搜索框、分组标题、行(左名称 右值)、选中行填充、底部动作栏。
- 先套到斜杠命令弹层(截图 2)、会话列表(截图 4)、连接服务(截图 6),再做设置对话框(截图 3,值可用 ←/→ 切换)。
- 验收:四个界面共用同一组件,键盘上下/回车/esc/搜索一致。

**阶段 3:会话视图**
- 用户消息左竖线、思考折叠行(`+ Thought · 时长`)、回复尾行(模式、模型、耗时、tok/s)。
- 右侧栏(标题、Context 用量),窄终端自动收起;底部状态行。
- 会话标签条(截图 5 顶部)是否要做,待定:omp 现在一个进程一个会话,标签条意味着多会话切换,代价大。

**阶段 4(可选)**:主题色对齐、动画关闭选项、`shift+tab` 切换模式的可见反馈。

## 4. 风险与约束

| 风险 | 应对 |
|---|---|
| `interactive-mode.ts` 体量大,改动易牵连 | 每阶段只动"渲染层",不改会话、工具、权限逻辑;先加后换,旧形状保留为可选项 |
| 终端宽度、CJK 宽字符、IME 光标 | 所有新组件走现有的宽度与截断工具(`visibleWidth`、`truncateToWidth`),并做 80/120 列两档的 pty 渲染检查 |
| 界面版本和桌面端各自演进 | 本改版只影响终端界面;桌面端不受影响 |
| 内核改动要重新编译二进制并替换桌面端内置内核 | 按 AGENTS.md:先验证开发产物,不替换正在使用的内核;发布时随桌面端版本一并更新 |
| 不复制 OpenCode 的品牌 | logo、名称、文案用 NPi 的;只借鉴布局与交互规范 |

## 5. 验证办法

用伪终端(pty)启动 `npi`,把输出喂给 xterm.js 渲染并截图,与参考图并排对比;不依赖真实用户数据(用临时 `HOME` 与目录)。首次运行的设置向导会占住首屏,需要在伪终端里先走完或预置设置。

## 6. 本轮实施记录

- 首页使用居中 Rail 输入框，高度自适应；框内底行为 Build / Plan / Goal、模型和服务商，框外显示真实绑定的快捷键，首页页脚为左目录、右版本。Shell / Python / Plan 的占位提示随模式变化。
- 命令弹层、设置、会话、服务连接共用 `chrome/list-dialog.ts` 框架。命令列表位于输入框上方，另外三类列表居中打开，保留搜索、鼠标操作、确认与取消逻辑。
- 设置：搜索跨页生效，简单值可用左右键切换，Ctrl+左右键切换页签；子菜单保留独立输入与 Esc 返回。
- 会话：用户标题与日期分组；Ctrl+D 删除、Ctrl+R 重命名、Ctrl+A 切换项目范围，原来的 Delete、F2、Tab 继续可用。
- 服务连接：Popular / Services 分组，始终提供搜索，选中行填充强调色；保留授权、凭据验证和禁用服务商过滤逻辑。
- 普通 ANSI CLI 的思考内容默认折叠，保留 Thinking / Thought 摘要；Ctrl+T 展开/收起，设置 `expandThinkingBlocks` 可保留选择，不删除历史中的原始思考内容。
- 快捷键按实际行为适配：Ctrl+P 仍切换模型，命令通过 `/` 打开；Shift+Tab 仍切换思考级别，Alt+A 打开 Agent Hub。上方参考图里的快捷键不直接覆盖已有绑定。
- 已用隔离数据检查源码渲染快照，定向覆盖中文消息、窄列、搜索、鼠标、删除确认和思考流式更新；真实账号的连接服务流程仍待用户确认，未宣称内核全量测试通过。

- 融合 OpenCode 输入框模板：面板为空行、输入、空行、框内“模式 · 模型 · 服务商”、半块字符收口，框外是快捷键提示行；与 OpenCode 一致。主页居中（logo、最宽 75 列的输入框、页脚目录与版本）此前已对齐。
