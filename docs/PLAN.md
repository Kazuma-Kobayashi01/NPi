# NPi · Academic 模式 — 产品与技术计划

> *Ars longa, vita brevis.* 论文写作是一件漫长的事；这个模式的目标是把它缩短，
> 同时不让它变得轻浮。

状态：**草案 v0.1**（2026-10-31）· 目标版本：**1.1.0** · 负责人：Kazuma
本文是计划，不是承诺。每个阶段结束时回来修订它。

---

## 1. 为什么做，做给谁

**用户**：写论文的人——研究生、博士后、青年教师、工业界研究员。他们的日常是：

1. 读大量英文（或其他语言）论文，需要**对照翻译**而不是“翻译完就丢了原文”；
2. 在 LaTeX 里写论文，公式、引用、图表样样要对；
3. 为论文画**可复现的图**，且符合期刊栏宽、配色、字体；
4. 投稿前想先被“挑刺”，投稿后要写 rebuttal；
5. 不放心把未发表的稿子交给一个会胡编参考文献的工具。

**定位**：Academic 是第三个房间（Chat · Code · **Academic**）。它不是 Chat 加几个按钮，
而是围绕**一篇论文**组织的工作区：稿件、参考文献、图、译文、审稿意见都在同一个文件夹里，
由同一个 agent 读写，并且每一步都留得下痕迹。

**不做什么（至少 1.1 不做）**

- 不做完整的 Overleaf 式云协作；不做多人实时编辑。
- 不做“一键生成整篇论文”。工具帮人写，不替人署名。
- 不做对**他人**待审稿件的审稿（见 §9 伦理）。
- 不碰期刊投稿系统。

## 2. 核心场景（验收用的故事）

| # | 故事 | 一句话验收 |
|---|---|---|
| S1 | 在聊天里问一个推导，答案里的公式能正确排版 | `$\nabla\cdot E=\rho/\varepsilon_0$` 和 `$$\int_0^\infty e^{-x^2}dx$$` 流式输出过程中不闪烁、不破版 |
| S2 | 打开一篇 PDF，右边出中文，**左右逐段对照**，滚动同步，术语统一 | 一篇 12 页论文翻译完，点任意中文段落能高亮对应英文段落 |
| S3 | 写 `main.tex`，实时预览 PDF，报错能点进行号 | 保存后 3 秒内出 PDF；编译错误显示为可点击的列表 |
| S4 | “把表 2 的 CSV 画成适合双栏的折线图，色盲友好” | 产出 PDF 矢量图 + 生成脚本 + 可粘贴的 `figure` 环境 |
| S5 | “以 NeurIPS 审稿人的口吻审我的论文” | 得到摘要/优点/缺点/问题/打分/建议，且每条意见**引用稿件中的具体位置** |
| S6 | 收到真实审稿意见，生成逐条回复的 rebuttal 草稿 | 每条意见对应一段回复，并指出稿件需要修改的位置，可导出 `response.tex` |
| S7 | 检查全文参考文献，发现一条根本不存在的引用 | 对每个 `\cite` 做真实性核验，列出“未找到 / 元数据不一致 / 已核实” |

**两条硬约束**（来自 `AGENTS.md` 和现有设计，必须遵守）：

1. **无 CDN、离线可用**：KaTeX、pdf.js 等必须**随应用打包**；CSP 保持严格（release 为 `script-src 'self'`）。
2. **webview 不能下发路径或命令**：编译 LaTeX、读取 PDF、写文件都走 Rust 命令，前端只传论文 id 与相对路径；路径校验、超时、进程树清理在 Rust 完成（沿用 `spawn_gate`、`child_run`）。

## 4. 信息架构：以“一篇论文”为单位

```
~/Documents/NPi/Papers/
└── attention-notes/                 一篇论文 = 一个文件夹（也是 agent 的 cwd）
    ├── .npi-paper.json              元数据：标题、领域、语言对、目标会议、引用格式、术语表引用
    ├── main.tex                     稿件（或 paper.md，二选一）
    ├── refs.bib                     参考文献库
    ├── sections/                    可选：按章节拆分
    ├── figures/                     图：fig-*.pdf + fig-*.py（脚本与产物同名）
    ├── translations/
    │   └── zh/                      译文：<源文件>.zh.md + 对齐索引 .align.json
    ├── reviews/
    │   └── 2026-11-02-neurips.md    模拟审稿记录，带版本号
    ├── snapshots/                   每次大改前的快照（可恢复）
    └── notes/                       阅读笔记、实验记录
```

- **快照**：不强制用户会用 git。每次 agent 批量修改前自动存快照；用户可在时间线里对比、回退。
- **元数据文件**是人类可读的 JSON，可手改、可进 git。
- 论文目录之外的 PDF（比如别人的论文）作为**参考资料**导入到 `notes/sources/`，不混进稿件。

## 5. 功能设计

### 5.1 数学与 LaTeX 显示（基础能力，最先做）

**目标**：Chat、Code、Academic 三个房间的 Markdown 都能正确显示公式。

- **引擎**：打包 **KaTeX**（JS + CSS + 字体，约 1 MB，同步渲染、体积小、够快）。
  不选 MathJax（体积与异步重排会让流式输出闪烁）。
- **语法**：`$…$`、`$$…$$`、`\(…\)`、`\[…\]`；代码块与行内代码里的 `$` 不处理；
  `\$` 是转义的美元符号；金额（`$5 and $10`）要有判别规则，避免误判。
- **marked 扩展**：在 `marked-setup.js` 增加 `math` 内联/块扩展，渲染器输出 KaTeX 的 HTML，
  参数 `trust: false`、`throwOnError: false`、`maxSize`/`maxExpand` 限制，防止恶意宏。
  现有规则“Markdown 里的原始 HTML 一律转义”**不放松**，KaTeX 输出只来自扩展本身。
- **流式渲染**：未闭合的 `$$` 在流式过程中**先按文本显示**，闭合后一次性替换；
  已渲染的公式缓存（相同源码不重算）。
- **宏与编号**：支持 `\newcommand` 一类宏（来自 `.npi-paper.json` 的 `macros`），
  `\tag{}` 与 `equation` 环境的编号；复制公式 → 右键“复制 LaTeX 源码”。
- **LaTeX 片段预览**：`tabular`、`algorithm`、`tikzpicture` 等 KaTeX 不支持的环境，
  走 §5.2 的本地编译，在对话里以 SVG 内嵌。
- **测试**：`test-markdown.mjs` 增加数学用例（含恶意输入）；新增 `test-math.mjs`
  覆盖分隔符判定、转义、金额、未闭合、中文标点相邻等边界。

### 5.2 LaTeX 排版与预览（稿件的“眼睛”）

**目标**：写 `main.tex`，保存即得 PDF，错误可定位。

- **引擎探测**：设置里选择并检测 `tectonic`（首选，体积小、自动取包）、`latexmk`、`xelatex`、`lualatex`。
  先不打包 TeX 发行版（MacTeX 约 5 GB）；提供“安装 Tectonic”的指引，
  Tectonic 作为可选下载（遵守“下载前告知文件名、来源、大小并取得同意”）。
- **编译**（Rust `latex_build.rs`）：
  - 命令固定为白名单（不接受前端传来的参数），默认 `-no-shell-escape`、
    限制输出目录于论文文件夹内、超时（默认 60 秒）、进程树清理；
  - 解析 `.log`，把错误/警告整理成 `{file, line, message, hint}`，前端显示为可点击列表；
  - 增量编译与防抖，同一论文同时只跑一次。
- **预览**：打包 **pdf.js**，在右侧栏或独立分栏渲染 PDF（页缩略图、缩放、文本选择、
  从 PDF 反向定位源码行 = SyncTeX 的二期目标）。PDF 字节经 Rust 命令读出，前端用 blob 显示，
  不开启 asset 协议。
- **编辑**：不自造代码编辑器。稿件在外部编辑器（或 agent）里改，NPi 监视文件变化并刷新；
  内嵌的轻量编辑只用于“应用某条修改建议”。
- **模板库**：常用会议/期刊模板（NeurIPS、ICLR、ACL、IEEE、Springer LNCS、Nature 类、通用 article），
  每个标注许可证与来源；只打包许可证允许再分发的。

### 5.3 左右对照翻译（旗舰功能）

**目标**：读论文时原文与译文并排，逐段对齐，术语一致，公式与引用不被破坏。

**输入**：PDF、`.tex`、`.md`、网页（后者二期）。

**流程**

1. **提取与分段**
   - `.tex`/`.md`：按段落/环境分段，保留结构；
   - PDF：用 pdf.js 文本层提取，再做版面重建（双栏、页眉页脚、脚注、图表标题、参考文献去噪）；
     扫描件的 OCR 作为二期（本地 OCR，不上传）。
2. **保护不可译内容**：公式、`\cite{}`、`\ref{}`、URL、代码、变量名先替换为占位符
   （`⟦M1⟧`），翻译后还原，并**校验占位符数量与顺序一致**，不一致则自动重译该段。
3. **术语表**：每篇论文一份 `glossary.json`（原词 → 译词，含大小写与词性提示），
   提示词里注入；翻译完成后扫描全文检查术语是否统一，列出冲突供人工裁定。
4. **翻译**：按段落并发、带上下文窗口（前后各 1–2 段 + 章节标题）、缓存已译段落；
   长论文先译摘要和引言作“风格样例”，后文参考。
5. **对齐索引** `*.align.json`：`[{id, src:[start,end], tgt:[start,end], status}]`，
   是双栏同步滚动、点击高亮、增量更新的基础。

**界面**

- 左原文 / 右译文，**同步滚动**（以段落锚点对齐，而非按像素比例）；
- 点任一侧段落，另一侧高亮并滚到位；
- 每段有小工具条：重译、改写（更学术/更口语）、编辑、锁定、标记“有疑问”；
- 顶部：语言对切换、术语表入口、翻译进度（已译/总段、预计用量与花费）、导出；
- 译文可手改；手改过的段落标为“人工”，后续重译不覆盖。

**导出**：双语对照 PDF/HTML（并排或上下）、仅译文 Markdown/LaTeX（`ctex`）、术语表 CSV。

**质量保障**：回译抽检（随机抽 5% 段落回译，与原文做语义比对并报告偏差）、数字与单位一致性检查、
公式占位符校验、漏译检测（译文长度比例异常）。

### 5.4 论文写作辅助

- **章节感知**：agent 知道当前在写摘要/引言/相关工作/方法/实验/讨论，
  按各章的惯例给出结构与措辞建议；
- **大纲与论证**：生成/检查论证链（问题 → 缺口 → 贡献 → 证据），指出“声称了但没证据”的句子；
- **润色以“修订记录”呈现**：所有改写以逐句 diff（接受/拒绝）展示，**默认不直接覆盖原文**；
- **一致性检查**：符号、缩写首次定义、术语前后不一、时态、图表引用是否都在正文被引用；
- **篇幅与格式**：按目标会议的页数/字数上限给出提示；摘要字数、关键词数；
- **语言**：中英互改的学术语气；不做“降低 AI 检测率”之类功能（不鼓励也不支持）。

### 5.5 论文图生成

**原则：图必须来自真实数据与可复现的代码，工具不得凭空编造数据点。**

- **代码出图**：agent 写 `figures/fig-xxx.py`（matplotlib/seaborn）、TikZ/pgfplots、Graphviz、Mermaid；
  在**论文目录的沙箱**里运行，产出 PDF/SVG 矢量图 + 同名脚本；
- **期刊样式预设**：单栏 3.4 in / 双栏 7.0 in、字体与正文一致、字号 ≥ 8 pt、
  色盲友好调色板、灰度可读、线型/标记双编码、统一图例位置；
- **环境**：优先使用系统 `python3`；可选使用 DevStore 的 Miniconda 环境（若已挂载）；
  缺包时提示而非自动安装；
- **图库面板**（右栏卡片）：缩略图、来源脚本、数据文件、最后更新时间、被正文引用的位置；
  数据变了可“一键重绘”；
- **LaTeX 片段**：生成 `\begin{figure}…\caption{…}\label{fig:…}…\end{figure}`，
  并提示正文里应出现的 `Figure~\ref{fig:…}`；
- **概念示意图**（流程图、架构图）：优先 TikZ/Mermaid 的代码图；
  图像生成模型仅用于示意性插图，且在图上与元数据里标注“生成”，不用于结果图；
- **数据→表格**：CSV → `booktabs` 表格，自动加粗最优值、对齐小数点、生成 `\caption`。

### 5.6 模拟审稿与 rebuttal

**定位**：投稿前的“演习”，**不是**真实审稿的替代，界面上始终标明“模拟”。

- **审稿人角色**：方法学家、领域专家、统计学家、挑剔的新手、宽容的老教授、
  “只读摘要和图表的匆忙审稿人”；可多人并行，再由**领域主席（AC）**角色汇总元评审；
- **会议/期刊模板**：NeurIPS / ICLR / ICML / ACL（ARR）/ CVPR / IEEE Trans / Nature 类，
  评审表字段与评分口径各异（摘要、优点、缺点、问题、局限、伦理、可复现性、
  评分与置信度、推荐意见）；
- **有据可查**：每条意见必须**引用稿件的具体位置**（章节/行/图表）；
  不能引用的意见标为“笼统意见”并降权；
- **问题清单化**：把意见转成任务（修改建议、需补实验、需补引用），挂到右栏“审稿意见”卡片，
  处理完可勾掉；
- **rebuttal 助手**：导入真实审稿意见（粘贴或文件），逐条拆解，起草回复
  （礼貌、具体、承诺修改且指向稿件位置）、给出“该补的实验”清单，
  导出 `response.tex` / Markdown；
- **版本对比**：投稿版 → 修改版的 diff，自动生成“修改说明”（change log）；
- **校准**：提供若干公开的审稿示例作为风格参照，避免模拟审稿“千篇一律地夸/骂”。

### 5.7 参考文献与引用真实性

**这是学术场景里最不能出错的一块**：大模型会编造看起来很真的参考文献。

- **文献库**：`refs.bib` 的解析、去重、规范化（作者名、会议名缩写、DOI）；
  导入 Zotero/EndNote 导出；
- **插入引用**：在 agent 对话中按“主题/作者/标题”检索 → 插入 `\cite{key}`，同时写入 `refs.bib`；
- **真实性核验**（联网，需用户在设置里开启，默认关闭）：
  对每个条目查 Crossref / OpenAlex / arXiv / DBLP，比对标题、作者、年份、DOI；
  结果三态：**已核实 / 元数据不一致 / 未找到**；
  agent **不得在未核验的情况下新增文献**，新增时必须附检索来源；
- **引文风格**：CSL 驱动（APA、IEEE、GB/T 7714 等），Markdown 稿件也能用；
- **读论文问答**：对导入的 PDF 做**带页码出处**的问答（检索增强，答案里每个论断标 `[p.7]`），
  找不到依据时明说“原文未提及”。

### 5.8 其他值得做的（排在后面）

- **公式 OCR**：截图/PDF 区域 → LaTeX，右侧实时预览并可编辑；
- **符号检查/推导校验**：对关键推导调用 CAS（如 sympy）做数值抽检；
- **表格 OCR**；
- **阅读模式**：高亮方法/结论/局限，生成“一页纸摘要”，领域内相关工作地图；
- **投稿检查清单**：匿名化检查（作者名、致谢、自引、元数据）、图表可读性、参考文献格式、
  伦理与数据声明；
- **Zotero 联动**、**Obsidian/Markdown 笔记导出**；
- **本地模型**（见 §9）与**离线模式**。

## 6. 界面与交互

- **模式开关**：顶栏分段控件变为三段（对话 / 代码 / 学术，学术用书本或学位帽图标）；
  切换仍回到该房间的起始页。
- **起始页**：问候沿用（每个房间有自己的句子，加入学术版若干条，例如
  “Which paper today, {name}?”、“Reading or writing, {name}?”），
  下方是**四个入口卡片**：写作 · 翻译 · 图 · 审稿，以及最近的论文。
- **侧栏**：论文列表；展开后是该论文的 稿件 / 译文 / 图 / 审稿记录；右键菜单沿用
  （置顶、重命名、归档、在 Finder 中显示）。
- **工作区布局**：中间是对话；右侧栏默认显示 **大纲 / 引用 / 图 / 审稿意见**；
  需要时拉出**文档分栏**（稿件预览 PDF，或翻译双栏）。
  沿用“分栏从右侧新增”的约定与可拖拽宽度。
- **视觉**：沿用人文主义风格；译文与公式使用衬线体，数学字体用 KaTeX 自带；
  PDF/双栏区域使用更窄的边距与更高的信息密度，但不引入新的主题色。
- **界面详细程度（5 档）**：学术工具容易“功能过载”，各档位的取舍在 `app/ui-detail.js` 里统一管理。

### 7.2 Rust（`desktop/src-tauri/src/`）

| 新增 | 作用 |
|---|---|
| `academic_space.rs` | 论文根目录、`.npi-paper.json` 读写、快照、术语表；与 `chat_space.rs` 同一风格 |

| `paper_files.rs` | 论文目录内的安全读写（路径校验，拒绝越界与符号链接逃逸，参照 `project_file.rs`） |
| `bib.rs` | BibTeX 解析/规范化/去重 |

| 扩展 `app_mode.rs` | `AppMode::Academic` + 提示词 |

每个模块按 `AGENTS.md` 要求带测试；命令注册进 `generate_handler!`；
新的 RPC 命令若需要，加入 `ALLOWED_COMMAND_TYPES`。

### 7.3 Agent 层（`omp/`，`npi` 分支）

- 用**技能（skills）**承载论文工作流：`paper-write`、`paper-translate`、`paper-review`、
  `paper-figure`、`paper-cite`，每个技能带明确的输入输出约定和自检步骤；
- Academic 系统提示词：**替换**默认提示词（同 Chat），内容包括：诚信约束（不编造引用与数据）、
  不覆盖原文只给修订、数学用 LaTeX、引用必须有来源、遇到不确定明说；
- 工具权限：Academic 默认审批模式为 “write”（改文件要确认）；删除文件始终要确认；
- 命令行同步：`npi paper …` 子命令（编译、核验引用、导出译文）与桌面端共用同一实现，
  方便脚本化与 CI。

### 7.4 数据与隔离

- 论文数据在 `~/Documents/NPi/Papers/`，与代码项目、聊天分开；
- 全局设置、登录、会话仍在 `~/.local/share/npi`；
- 联网功能（引用核验、模板下载）都有**独立开关**，默认关闭，设置里写明会发送什么。

## 9. 风险、伦理与隐私

| 风险 | 对策 |
|---|---|
| **编造参考文献** | 默认策略：未核验不新增；核验结果三态可见；提示词与工具层都禁止“凭记忆写 BibTeX” |
| **编造数据/结果图** | 图只从用户提供的数据与可复现脚本生成；生成式插图必须标注 |
| **泄露未发表稿件** | 明示当前使用的模型提供方；论文级“仅本地模型/不联网”开关；日志不记录稿件正文到遥测（本来就没有遥测） |
| **用工具审他人稿件** | 多数会议/期刊**禁止**把待审稿件交给外部 LLM。审稿功能面向**自己的稿件**，界面与文档明确声明，不提供“导入待审稿件”的快捷入口 |
| **LaTeX 编译的安全** | 默认禁用 shell-escape；输出目录限制；超时与资源限制；白名单参数；错误不泄露绝对路径之外的信息 |
| **PDF 版面解析不准** | 允许人工修正分段；双栏与公式密集页面给出置信度提示；扫描件走 OCR 二期 |
| **数学流式渲染闪烁** | 未闭合不渲染、闭合后替换、缓存；用虚拟终端式的回归测试固定行为 |
| **学术诚信** | 不做“规避 AI 检测”；润色以修订记录呈现；README 与应用内说明“工具辅助，署名与责任在作者” |
| **体积与许可** | KaTeX/pdf.js 的许可证写入 `THIRD_PARTY_NOTICES.md`；模板只收许可证允许分发的；Tectonic 为可选下载 |
| **范围蔓延** | 以 §2 的七个故事为验收线；其余放 §5.8，不抢 M0–M7 |

## 10. 测试与质量

- **纯函数优先**：分段/占位符/对齐/数学分隔符/审稿模板转换都写成纯函数，
  配 `tests/test-*.mjs`，纳入 `npm test`；
- **夹具**：一组小型真实论文（公版或自写）覆盖：双栏 PDF、含公式的 `.tex`、含表格与算法的 `.tex`、
  中英混排 `.md`；
- **Rust**：路径校验、编译日志解析、bib 解析、核验结果合并都有单元测试；
  需要 TeX 引擎的测试在缺引擎时跳过，CI 里设环境变量强制要求；
- **人工验收清单**：每个里程碑写一页，按 §2 的故事逐条走一遍，截图存档；
- **性能预算**：打开 50 页 PDF 首屏 < 2 秒；翻译双栏滚动 60 fps；编译预览（中等稿件）< 5 秒。
