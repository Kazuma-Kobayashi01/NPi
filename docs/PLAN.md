# NPi · Academic 模式 — 产品与技术计划

> *Ars longa, vita brevis.* 论文写作是一件漫长的事；这个模式的目标是把它缩短，
> 同时不让它变得轻浮。

状态：**草案 v0.2**（2026-10-31，已按第一轮决定修订）· 目标版本：**1.1.0** · 负责人：Kazuma

本文是计划，不是承诺。每个阶段结束时回来修订它。

## 0. 已确认的决定（v0.2）

| 项 | 决定 | 对计划的影响 |
|---|---|---|
| TeX 引擎 | **必须兼容 Windows** | 引擎层做成平台中立的抽象；默认 Tectonic（三平台同一份二进制），兼容 MiKTeX / TeX Live；路径、进程、字体全部按跨平台写（§5.2） |
| 翻译语言 | **先只做 中↔英** | 术语表、排版规则、质检都只针对这一对；其他语言不留入口（§5.3） |
| 期刊/会议模板 | **先不考虑** | 模板库、按会议定制的评分口径整块延后；审稿用通用评审表（§5.6） |
| 稿件格式 | **LaTeX、Markdown、Word 三者都兼容** | 引入统一的“稿件中间表示”，三种格式的导入、翻译、审稿、导出都要走通（§4.1、§5.3） |
| 联网 | **先不做** | 引用联网核验整块延后；1.1 只做本地检查，并用规则禁止 agent 编造文献（§5.7） |
| 命令行子命令 | **先不做** | 不做 `npi paper …`；agent 能力通过 **MCP + Skills** 暴露（§7.5） |
| 接入方式 | **接入对应 MCP、Skills** | 新增 §7.5：一个随应用提供的本地 MCP 服务、一组随应用提供的技能，以及可选的第三方 MCP |

## 1. 为什么做，做给谁

**用户**：写论文的人——研究生、博士后、青年教师、工业界研究员。他们的日常是：

1. 读大量英文（或其他语言）论文，需要**对照翻译**而不是“翻译完就丢了原文”；
2. 在 LaTeX 里写论文，公式、引用、图表样样要对；
3. 为论文画**可复现的图**，且符合期刊栏宽、配色、字体；
4. 投稿前想先被“挑刺”，投稿后要写 rebuttal；
5. 不放心把未发表的稿子交给一个会胡编参考文献的工具。

**定位**：Academic 是第三个房间（Chat · Code · **Academic**）。它不是 Chat 加几个按钮，
而是围绕**一篇论文**组织的工作区：稿件、参考文献、图、译文、审稿意见都在同一个文件夹里，
由同一个 agent 读写，并且每一步都留得下痕迹。

**不做什么（至少 1.1 不做）**

- 不做完整的 Overleaf 式云协作；不做多人实时编辑。
- 不做“一键生成整篇论文”。工具帮人写，不替人署名。
- 不做对**他人**待审稿件的审稿（见 §9 伦理）。
- 不碰期刊投稿系统。
- 1.1 **不联网核验**引用、**不做**期刊模板、**不做** `npi paper` 子命令、**只做**中英互译（见 §0）。

## 2. 核心场景（验收用的故事）

| # | 故事 | 一句话验收 |
|---|---|---|
| S1 | 在聊天里问一个推导，答案里的公式能正确排版 | `$\nabla\cdot E=\rho/\varepsilon_0$` 和 `$$\int_0^\infty e^{-x^2}dx$$` 流式输出过程中不闪烁、不破版 |
| S2 | 打开一篇 PDF、Word 或 Markdown，另一侧出对应译文（中↔英），**左右逐段对照**，滚动同步，术语统一 | 一篇 12 页论文翻译完，点任意译文段落能高亮对应原文段落；Word 译文保留样式 |
| S3 | 写 `main.tex`，实时预览 PDF，报错能点进行号 | 保存后 3 秒内出 PDF；编译错误显示为可点击的列表 |
| S4 | “把表 2 的 CSV 画成适合双栏的折线图，色盲友好” | 产出 PDF 矢量图 + 生成脚本 + 可粘贴的 `figure` 环境 |
| S5 | “以 NeurIPS 审稿人的口吻审我的论文” | 得到摘要/优点/缺点/问题/打分/建议，且每条意见**引用稿件中的具体位置** |
| S6 | 收到真实审稿意见，生成逐条回复的 rebuttal 草稿 | 每条意见对应一段回复，并指出稿件需要修改的位置，可导出 `response.tex` |

## 4. 信息架构：以“一篇论文”为单位

```
~/Documents/NPi/Papers/
└── attention-notes/                 一篇论文 = 一个文件夹（也是 agent 的 cwd）
    ├── .npi-paper.json              元数据：标题、领域、语言对、目标会议、引用格式、术语表引用
    ├── main.tex                     稿件（或 paper.md，二选一）
    ├── refs.bib                     参考文献库
    ├── sections/                    可选：按章节拆分
    ├── figures/                     图：fig-*.pdf + fig-*.py（脚本与产物同名）
    ├── translations/
    │   └── zh/                      译文：<源文件>.zh.md + 对齐索引 .align.json
    ├── reviews/
    │   └── 2026-11-02-neurips.md    模拟审稿记录，带版本号
    ├── snapshots/                   每次大改前的快照（可恢复）
    └── notes/                       阅读笔记、实验记录
```

- **快照**：不强制用户会用 git。每次 agent 批量修改前自动存快照；用户可在时间线里对比、回退。
- **元数据文件**是人类可读的 JSON，可手改、可进 git。
- 论文目录之外的 PDF（比如别人的论文）作为**参考资料**导入到 `notes/sources/`，不混进稿件。

### 4.1 三种稿件格式与统一中间表示

稿件可以是 **LaTeX（`.tex`）**、**Markdown（`.md`）** 或 **Word（`.docx`）**。三者通过一个**稿件中间表示**（下称 IR）打通，
这样翻译、审稿、写作辅助只实现一次：

```
 .tex ─┐                                   ┌─ 对照翻译 / 译文导出
 .md  ─┼─► 解析 ─► IR（块级结构 + 行内 + 公式 + 引用 + 图表） ─► agent 工作流 ─┼─ 审稿意见（带位置）
 .docx ┘                                   └─ 写作修订（diff）
```

- **IR 的要素**：章节树、段落/列表/表格/图块/公式块、行内公式、引用（`\cite{}` 或 Word 域/文献管理器字段）、
  交叉引用、脚注；每个块有稳定 `id` 和**原文件内的定位**（`.tex` 行区间、`.md` 行区间、`.docx` 的段落序号与 run 范围）。
- **以原格式为准**：IR 只是工作表示。**回写永远落到原格式的原位置**（改 `.tex` 就改 `.tex`），不把 Word 稿悄悄转成 LaTeX。
- **LaTeX**：自写轻量解析（环境、命令、数学、`\input`/`\include` 展开），不追求完整 TeX 语义；解析不了的片段原样保护为“不可译块”。
- **Markdown**：沿用 marked 的词法分析，扩展数学与脚注。
- **Word（.docx）**：解压读取 `document.xml`，按段落分块，**以 run 为单位处理文字**，从而在翻译时**保留样式**（加粗、斜体、字号、样式名）；
  Word 公式（OMML）、图片、批注、修订标记作为受保护节点原样保留；导出译文时写回同样的 run 结构。
  模拟审稿的意见可导出为 **Word 批注**。库选型：Rust 侧用 `zip` + `quick-xml` 自行读写（可控、体积小），
  不依赖 pandoc（体积与许可复杂）；pandoc 仅作为用户自备时的**可选**转换器（用于 .docx ⇄ .md 的粗转换）。
- **互转的边界**：`.docx → .md/.tex` 是**有损**的，只用于阅读与分析，界面上明确标注“有损”；不承诺往返无损。

## 5. 功能设计

### 5.1 数学与 LaTeX 显示（基础能力，最先做）

**目标**：Chat、Code、Academic 三个房间的 Markdown 都能正确显示公式。

- **引擎**：打包 **KaTeX**（JS + CSS + 字体，约 1 MB，同步渲染、体积小、够快）。
  不选 MathJax（体积与异步重排会让流式输出闪烁）。
- **语法**：`$…$`、`$$…$$`、`\(…\)`、`\[…\]`；代码块与行内代码里的 `$` 不处理；
  `\$` 是转义的美元符号；金额（`$5 and $10`）要有判别规则，避免误判。
- **marked 扩展**：在 `marked-setup.js` 增加 `math` 内联/块扩展，渲染器输出 KaTeX 的 HTML，
  参数 `trust: false`、`throwOnError: false`、`maxSize`/`maxExpand` 限制，防止恶意宏。
  现有规则“Markdown 里的原始 HTML 一律转义”**不放松**，KaTeX 输出只来自扩展本身。
- **流式渲染**：未闭合的 `$$` 在流式过程中**先按文本显示**，闭合后一次性替换；
  已渲染的公式缓存（相同源码不重算）。
- **宏与编号**：支持 `\newcommand` 一类宏（来自 `.npi-paper.json` 的 `macros`），
  `\tag{}` 与 `equation` 环境的编号；复制公式 → 右键“复制 LaTeX 源码”。
- **LaTeX 片段预览**：`tabular`、`algorithm`、`tikzpicture` 等 KaTeX 不支持的环境，
  走 §5.2 的本地编译，在对话里以 SVG 内嵌。
- **测试**：`test-markdown.mjs` 增加数学用例（含恶意输入）；新增 `test-math.mjs`
  覆盖分隔符判定、转义、金额、未闭合、中文标点相邻等边界。

### 5.2 LaTeX 排版与预览（稿件的“眼睛”）

**目标**：写 `main.tex`，保存即得 PDF，错误可定位；**macOS 与 Windows 行为一致**。

- **引擎抽象**：定义 `TexEngine` 接口（`detect() / version() / compile(job) -> {pdf, log}`），实现 `Tectonic`、`Latexmk`、`Xelatex`、`Lualatex`、`Pdflatex` 五个后端。
  **默认 Tectonic**：单个可执行文件、三平台一致、自动按需取包，最适合“开箱即用”；
  用户已装 **MiKTeX（Windows 常见）/ TeX Live / MacTeX** 时自动识别并可切换。
- **安装引导**：设置里显示“已检测到的引擎”和一键“安装 Tectonic”的指引；
  Tectonic 作为**可选下载**（下载前告知文件名、来源、大小并取得同意），按平台选正确的构建，校验 SHA-256。
  1.1 **不打包** TeX 发行版（体积过大）。
- **中文排版**：默认用 `ctex` + XeTeX 路线（Tectonic 原生是 XeTeX）；字体按平台回退——
  macOS：Songti SC / PingFang SC；Windows：SimSun / Microsoft YaHei；也允许在设置里指定；缺字体时给出明确提示而不是静默出方块。
- **编译**（Rust `latex_build.rs`）：
  - 命令参数白名单（前端不能传参数），默认**禁用 shell-escape**，输出目录限制在论文文件夹内，超时（默认 60 秒），进程树清理
    （沿用 `supervisor`：macOS/Linux 进程组，**Windows Job Object**）；
  - 解析 `.log` 得到 `{file, line, message, hint}`，前端显示为可点击的错误列表；
  - 同一论文同时只跑一次，防抖，增量编译。
- **Windows 专项**：不显示控制台窗口（`CREATE_NO_WINDOW`，现有 `spawn.rs` 已有先例）；路径含空格/中文/UNC 前缀；`\r\n` 行尾；
  引擎探测同时看 PATH 与 MiKTeX 默认安装位置；长路径；杀软对 Tectonic 取包的拦截提示。
  **在 CI 里加 Windows runner**（GitHub Actions）跑编译用例与路径校验用例，不只靠本机验证。
- **预览**：打包 **pdf.js**（平台中立），在右侧栏或独立分栏渲染 PDF（页缩略图、缩放、文本选择；SyncTeX 反向定位列为二期）。
  PDF 字节经 Rust 命令读出、前端用 blob 显示，不开启 asset 协议。
- **编辑**：不自造代码编辑器。稿件在外部编辑器（或 agent）里改，NPi 监视文件变化并刷新；内嵌的轻量编辑只用于“应用某条修改建议”。
- **模板**：**1.1 不做期刊/会议模板**。只提供“通用 article / 中文 ctexart / beamer 无”的最小起步文件。

### 5.3 左右对照翻译（旗舰功能）

**目标**：读论文时原文与译文并排，逐段对齐，术语一致，公式与引用不被破坏。

**语言**：**只做 中文 ↔ 英文**（自动判断方向，也可手动指定）。其他语言本版不开放、不留入口。

**输入**：`.tex`、`.md`、`.docx`、PDF（网页二期）。

**流程**

1. **提取与分段**（经 §4.1 的稿件 IR）
   - `.tex`/`.md`：按段落/环境分段，保留结构；
   - `.docx`：按段落分块，**以 run 为单位翻译并保留样式**，公式（OMML）、图片、批注、修订标记原样保留；
   - PDF：用 pdf.js 文本层提取，再做版面重建（双栏、页眉页脚、脚注、图表标题、参考文献去噪）；
     扫描件的 OCR 作为二期（本地 OCR，不上传）。
2. **保护不可译内容**：公式、`\cite{}`、`\ref{}`、URL、代码、变量名先替换为占位符
   （`⟦M1⟧`），翻译后还原，并**校验占位符数量与顺序一致**，不一致则自动重译该段。
3. **术语表**：每篇论文一份 `glossary.json`（原词 → 译词，含大小写与词性提示），
   提示词里注入；翻译完成后扫描全文检查术语是否统一，列出冲突供人工裁定。
4. **翻译**：按段落并发、带上下文窗口（前后各 1–2 段 + 章节标题）、缓存已译段落；
   长论文先译摘要和引言作“风格样例”，后文参考。
5. **对齐索引** `*.align.json`：`[{id, src:[start,end], tgt:[start,end], status}]`，
   是双栏同步滚动、点击高亮、增量更新的基础。

**界面**

- 左原文 / 右译文，**同步滚动**（以段落锚点对齐，而非按像素比例）；
- 点任一侧段落，另一侧高亮并滚到位；
- 每段有小工具条：重译、改写（更学术/更口语）、编辑、锁定、标记“有疑问”；
- 顶部：语言对切换、术语表入口、翻译进度（已译/总段、预计用量与花费）、导出；
- 译文可手改；手改过的段落标为“人工”，后续重译不覆盖。

**导出**：双语对照 PDF/HTML（并排或上下）；**译文按原格式导出**（`.tex` 用 `ctex`、`.md`、`.docx` 保留样式）；术语表 CSV。

**中英专项规则**

- 中文译文用全角标点，中英文与数字之间的空格按统一规则处理，引号用“”；
- 英文译文遵循学术写作惯例（主动/被动、时态、缩写首次定义）；
- 人名、机构、方法名、数据集名默认保留原文，术语表可覆盖；
- 数字、单位、百分号、区间的写法在两种语言间保持一致并做校验。

**质量保障**：回译抽检（随机抽 5% 段落回译，与原文做语义比对并报告偏差）、数字与单位一致性检查、
公式占位符校验、漏译检测（译文长度比例异常）。

### 5.4 论文写作辅助

- **章节感知**：agent 知道当前在写摘要/引言/相关工作/方法/实验/讨论，
  按各章的惯例给出结构与措辞建议；
- **大纲与论证**：生成/检查论证链（问题 → 缺口 → 贡献 → 证据），指出“声称了但没证据”的句子；
- **润色以“修订记录”呈现**：所有改写以逐句 diff（接受/拒绝）展示，**默认不直接覆盖原文**；
- **一致性检查**：符号、缩写首次定义、术语前后不一、时态、图表引用是否都在正文被引用；
- **篇幅与格式**：按目标会议的页数/字数上限给出提示；摘要字数、关键词数；
- **语言**：中英互改的学术语气（仅此两种）；不做“降低 AI 检测率”之类功能（不鼓励也不支持）。

### 5.5 论文图生成

**原则：图必须来自真实数据与可复现的代码，工具不得凭空编造数据点。**

- **代码出图**：agent 写 `figures/fig-xxx.py`（matplotlib/seaborn）、TikZ/pgfplots、Graphviz、Mermaid；
  在**论文目录的沙箱**里运行，产出 PDF/SVG 矢量图 + 同名脚本；
- **期刊样式预设**：单栏 3.4 in / 双栏 7.0 in、字体与正文一致、字号 ≥ 8 pt、
  色盲友好调色板、灰度可读、线型/标记双编码、统一图例位置；
- **环境**：优先使用系统 `python3`；可选使用 DevStore 的 Miniconda 环境（若已挂载）；
  缺包时提示而非自动安装；
- **图库面板**（右栏卡片）：缩略图、来源脚本、数据文件、最后更新时间、被正文引用的位置；
  数据变了可“一键重绘”；
- **LaTeX 片段**：生成 `\begin{figure}…\caption{…}\label{fig:…}…\end{figure}`，
  并提示正文里应出现的 `Figure~\ref{fig:…}`；
- **概念示意图**（流程图、架构图）：优先 TikZ/Mermaid 的代码图；
  图像生成模型仅用于示意性插图，且在图上与元数据里标注“生成”，不用于结果图；
- **数据→表格**：CSV → `booktabs` 表格，自动加粗最优值、对齐小数点、生成 `\caption`。

### 5.6 模拟审稿与 rebuttal

**定位**：投稿前的“演习”，**不是**真实审稿的替代，界面上始终标明“模拟”。

- **审稿人角色**：方法学家、领域专家、统计学家、挑剔的新手、宽容的老教授、
  “只读摘要和图表的匆忙审稿人”；可多人并行，再由**领域主席（AC）**角色汇总元评审；
- **评审表**：本版只做一份**通用评审表**（摘要、优点、缺点、问题、局限、伦理、可复现性、
  评分与置信度、推荐意见）；**按会议/期刊定制的评分口径与模板整块延后**；
- **有据可查**：每条意见必须**引用稿件的具体位置**（章节/行/图表）；
  不能引用的意见标为“笼统意见”并降权；
- **问题清单化**：把意见转成任务（修改建议、需补实验、需补引用），挂到右栏“审稿意见”卡片，
  处理完可勾掉；
- **rebuttal 助手**：导入真实审稿意见（粘贴或文件），逐条拆解，起草回复
  （礼貌、具体、承诺修改且指向稿件位置）、给出“该补的实验”清单，
  导出 `response.tex` / Markdown；
- **版本对比**：投稿版 → 修改版的 diff，自动生成“修改说明”（change log）；
- **输出到原格式**：意见可导出为 Markdown 报告、**Word 批注**（`.docx` 稿件直接在原位置加批注），LaTeX 稿可选生成批注文件（`todonotes` 风格）；
- **校准**：提供若干公开的审稿示例作为风格参照，避免模拟审稿“千篇一律地夸/骂”。

### 5.7 参考文献与引用（本版全部离线）

**这是学术场景里最不能出错的一块**：大模型会编造看起来很真的参考文献。
**联网核验本版不做**，所以本版靠**规则**和**本地检查**兜底：

- **文献库**：`refs.bib` 的解析、去重、规范化（作者名、会议名缩写、DOI 格式）；导入 Zotero/EndNote 的导出文件；
  Word 稿的文献管理器字段按文本保留，不改写；
- **本地检查**：`\cite` 的 key 是否都在库里、库里有没有从未被引用的条目、重复条目、必填字段缺失、年份/页码格式；
- **插入引用**：从**用户自己的 `refs.bib`、导入的 PDF 与笔记**里检索并插入 `\cite{key}`；
- **反编造规则**（写进 Academic 系统提示词与技能，并由 MCP 工具强制）：
  1. agent **不得凭记忆写出新的参考文献条目**；
  2. 若用户要求新增、而来源只有对话内容，条目一律标 `note = {unverified}`，界面显示“未核验”徽标；
  3. 引用某篇论文的具体论断时，必须能指向**用户提供的原文位置**，否则明说“未找到依据”；
- **引文风格**：CSL 驱动（APA、IEEE、GB/T 7714 等），Markdown 与 Word 稿也能用；
- **读论文问答**：对导入的 PDF 做**带页码出处**的本地问答（答案里每个论断标 `[p.7]`），找不到依据时明说“原文未提及”；
- **后续版本**：联网核验（Crossref / OpenAlex / arXiv / DBLP）作为**可选、默认关闭**的功能，
  届时作为独立的 MCP 工具加入，并逐项写明会发送什么数据。

### 5.8 其他值得做的（排在后面）

- **公式 OCR**：截图/PDF 区域 → LaTeX，右侧实时预览并可编辑；
- **符号检查/推导校验**：对关键推导调用 CAS（如 sympy）做数值抽检；
- **表格 OCR**；
- **阅读模式**：高亮方法/结论/局限，生成“一页纸摘要”，领域内相关工作地图；
- **投稿检查清单**：匿名化检查（作者名、致谢、自引、元数据）、图表可读性、参考文献格式、
  伦理与数据声明；
- **Zotero 联动**、**Obsidian/Markdown 笔记导出**；
- **本地模型**（见 §9）与**离线模式**。

## 6. 界面与交互

- **模式开关**：顶栏分段控件变为三段（对话 / 代码 / 学术，学术用书本或学位帽图标）；
  切换仍回到该房间的起始页。
- **起始页**：问候沿用（每个房间有自己的句子，加入学术版若干条，例如
  “Which paper today, {name}?”、“Reading or writing, {name}?”），
  下方是**四个入口卡片**：写作 · 翻译 · 图 · 审稿，以及最近的论文。
- **侧栏**：论文列表；展开后是该论文的 稿件 / 译文 / 图 / 审稿记录；右键菜单沿用
  （置顶、重命名、归档、在 Finder 中显示）。
- **工作区布局**：中间是对话；右侧栏默认显示 **大纲 / 引用 / 图 / 审稿意见**；
  需要时拉出**文档分栏**（稿件预览 PDF，或翻译双栏）。
  沿用“分栏从右侧新增”的约定与可拖拽宽度。
- **视觉**：沿用人文主义风格；译文与公式使用衬线体，数学字体用 KaTeX 自带；
  PDF/双栏区域使用更窄的边距与更高的信息密度，但不引入新的主题色。
- **界面详细程度（5 档）**：学术工具容易“功能过载”，各档位的取舍在 `app/ui-detail.js` 里统一管理。

| `design/academic/*.jsx` | 起始页卡片、论文侧栏、双栏翻译、PDF 预览、图库、审稿意见、引用核验面板 |

### 7.2 Rust（`desktop/src-tauri/src/`）

| 新增 | 作用 |
|---|---|
| `academic_space.rs` | 论文根目录、`.npi-paper.json` 读写、快照、术语表；与 `chat_space.rs` 同一风格 |
| `latex_build.rs` | 引擎探测、编译、日志解析（走 `spawn_gate`/`child_run`，白名单参数、超时、树清理） |
| `paper_files.rs` | 论文目录内的安全读写（路径校验，拒绝越界与符号链接逃逸，参照 `project_file.rs`） |
| `bib.rs` | BibTeX 解析/规范化/去重 |
| `docx.rs` | `.docx` 的读写：`zip` + `quick-xml`，按 run 处理文字、保护公式/图片/批注、写回批注 |
| `paper_ir.rs` | 稿件中间表示（IR）：`.tex` / `.md` / `.docx` 的解析与定位 |
| `papers_mcp.rs` | 本地 MCP 服务（stdio）：把上面的能力以工具形式暴露给 agent（§7.5） |

| 扩展 `app_mode.rs` | `AppMode::Academic` + 提示词 |

每个模块按 `AGENTS.md` 要求带测试；命令注册进 `generate_handler!`；
新的 RPC 命令若需要，加入 `ALLOWED_COMMAND_TYPES`。

### 7.3 Agent 层（`omp/`，`npi` 分支）

- 论文工作流以**技能（Skills）**承载，确定性的文档操作以**本地 MCP 工具**承载，详见 **§7.5**；
- Academic 系统提示词：**替换**默认提示词（同 Chat；技能列表仍会由 omp 追加，已验证），内容包括：
  诚信约束（不编造引用与数据）、不覆盖原文只给修订、数学用 LaTeX、引用必须有来源、遇到不确定明说；
- 工具权限：Academic 默认审批模式为 “write”（改文件要确认）；删除文件始终要确认；
- **不做 `npi paper …` 子命令**（本版决定）。需要脚本化时，由 MCP 服务与技能覆盖。

### 7.4 数据与隔离

- 论文数据在 `~/Documents/NPi/Papers/`，与代码项目、聊天分开；
- 全局设置、登录、会话仍在 `~/.local/share/npi`；
- 本版唯一会联网的动作是**用户主动触发的可选下载**（如 Tectonic 引擎）；引用联网核验与模板下载都已延后，到时各有**独立开关**、默认关闭，设置里写明会发送什么。

### 7.5 MCP 与技能（Skills）接入

omp 本身已经支持两者（`mcp.json`、`/mcp` 管理命令、`skills.*` 设置；技能列表即使系统提示词被替换也会追加，已用打包的 `npi` 验证）。
Academic 不另造机制，而是**往里面放内容**。

**A. 随应用提供的本地 MCP 服务：`npi-papers`**

为什么要有它：编译、解析、对齐、核验这些操作**必须确定、可测试、跨平台一致**，不能让模型临时拼 shell 命令。
同一份 Rust 实现既给界面用，也经 MCP 给 agent 用。

- **形态**：stdio 子进程，由应用的**同一个可执行文件**以内部参数启动（不是面向用户的子命令，因此不违背“先不做子命令”）；
  macOS 与 Windows 行为一致。
- **注册**：进入某篇论文时，应用在**该论文文件夹**的 `.omp/mcp.json` 写入这一项（只作用于这篇论文，不污染全局）；
  依赖 `mcp.enableProjectConfig`，首次启用时向用户确认。
- **工具清单（首批）**

  | 工具 | 作用 | 读/写 |
  |---|---|---|
  | `latex_compile` / `latex_log` | 编译并返回结构化错误 | 写（产物目录） |
  | `paper_outline` | 返回稿件的章节树与块 id（来自 IR） | 读 |
  | `paper_read_block` / `paper_apply_edit` | 读取一个块 / 以**修订**形式应用修改（默认写成建议，不覆盖原文） | 读 / 写 |
  | `pdf_text` | 按页提取文本与版面块 | 读 |
  | `docx_read` / `docx_write_comments` / `docx_write_translation` | 读取、写批注、写译文（保留样式） | 读 / 写 |
  | `segment_document` / `align_get` / `align_set` | 分段、读写对齐索引 | 读 / 写 |
  | `glossary_get` / `glossary_set` | 读写术语表 | 读 / 写 |
  | `bib_parse` / `bib_check` | 解析与**本地**检查（缺失 key、重复、字段不全） | 读 |
  | `bib_add` | 新增条目；**强制写入 `unverified` 标记**，且只接受带来源的参数 | 写 |
  | `figure_run` | 在论文目录沙箱内运行 `figures/*.py` 并登记产物 | 写 |

- **安全**：所有路径被限制在论文文件夹内（拒绝越界与符号链接逃逸）；不联网；调用有超时；
  写操作经 omp 的审批机制（`approval.rs` 里对 `mcp__npi-papers__*` 的读类工具默认放行，写类默认询问）。
- **契约测试**：用 JSON-RPC 夹具测每个工具的输入输出与拒绝路径；Windows runner 上同样跑。

**B. 随应用提供的技能（Skills）**

放在仓库 `desktop/resources/skills/academic/`，随应用安装；首次进入 Academic 时登记到 omp 的技能目录
（`skills.customDirectories`），升级时按版本覆盖，用户自己的同名技能优先。

| 技能 | 内容 | 调用的 MCP 工具 |
|---|---|---|
| `paper-write` | 章节感知的写作、大纲、论证检查、润色（以修订呈现） | `paper_outline`、`paper_read_block`、`paper_apply_edit` |
| `paper-translate` | 中↔英对照翻译：占位符保护、术语表、质检、分批 | `segment_document`、`glossary_*`、`align_*`、`docx_write_translation` |
| `paper-review` | 通用评审表、有据可查的意见、AC 汇总 | `paper_outline`、`paper_read_block`、`docx_write_comments` |
| `paper-rebuttal` | 拆解真实审稿意见、逐条起草回复、修改说明 | `paper_read_block`、`paper_apply_edit` |
| `paper-figure` | 期刊样式出图、可复现脚本、图注与 `figure` 环境 | `figure_run` |
| `paper-refs` | 本地参考文献检查与整理、反编造规则 | `bib_parse`、`bib_check`、`bib_add` |
| `paper-format` | 三种稿件格式之间的有损转换与说明 | `docx_read`、`paper_outline` |

- **形态**：每个技能是一个目录，含 `SKILL.md`（`name`、`description` 写成**便于检索的一句话**，正文含：何时使用、步骤、
  必须调用的工具、自检清单、**禁止事项**）和需要的模板文件；
- **范围控制**：Academic 只展示学术技能 + 用户自己的技能，避免 40 多个无关技能挤占提示词。
  实现上需要让 omp 在 Academic 会话里按名称过滤技能（`skills.includeSkills`）。
  现有约定是启动覆盖文件（`--config`）只放浏览器设置，所以这里要**扩展该覆盖文件的用途并更新对应的文档与测试**（`AGENTS.md` 里的不变量）；
- **质量门**：`scripts/lint-skills` 校验 frontmatter、描述长度、引用的工具是否存在；技能改动要带一个“冒烟问答”夹具。

**C. 可选的第三方 MCP（默认关闭，设置里“添加”）**

只推荐**本地**、不依赖外网的：Zotero 本地接口（读取已有文献库）、Pandoc（用户自备时做 `.docx ⇄ .md` 粗转换）、
Graphviz/Mermaid 渲染。联网类（arXiv、Semantic Scholar、Crossref）**随联网功能一起延后**。
文档里给出配置模板与风险说明，应用不替用户安装。

| 阶段 | 内容 | 体量 | 验收 |

| **M1 数学显示** | KaTeX 打包、marked 数学扩展、流式处理、复制源码、测试 | M | S1 通过；`test-math`、`test-markdown` 通过；三个房间都显示公式 |
| **M2 稿件 IR 与三种格式** | `paper_ir.rs`（`.tex`/`.md`）、`docx.rs`（读、保留样式的写回、批注）、`paper_apply_edit` 修订机制 | L | 三种格式都能读出章节树、定位块、写回修订；docx 往返不丢样式/公式/图片 |

## 9. 风险、伦理与隐私

| 风险 | 对策 |
|---|---|
| **编造参考文献** | 本版没有联网核验，所以靠规则：`bib_add` 只接受带来源的参数并强制标 `unverified`；提示词与技能都禁止“凭记忆写 BibTeX”；界面显示“未核验”徽标 |
| **编造数据/结果图** | 图只从用户提供的数据与可复现脚本生成；生成式插图必须标注 |
| **Windows 与 macOS 行为不一致**（路径、字体、进程、行尾） | 引擎抽象 + `Path` 一律不拼字符串 + CI 加 Windows runner + 中文字体回退表 |
| **Word 往返丢样式/公式** | 以 run 为单位处理文字、公式/图片/批注作为受保护节点；`.docx → .tex/.md` 明确标注“有损”；往返测试用例 |
| **泄露未发表稿件** | 明示当前使用的模型提供方；论文级“仅本地模型/不联网”开关；日志不记录稿件正文到遥测（本来就没有遥测） |
| **用工具审他人稿件** | 多数会议/期刊**禁止**把待审稿件交给外部 LLM。审稿功能面向**自己的稿件**，界面与文档明确声明，不提供“导入待审稿件”的快捷入口 |
| **LaTeX 编译的安全** | 默认禁用 shell-escape；输出目录限制；超时与资源限制；白名单参数；错误不泄露绝对路径之外的信息 |
| **PDF 版面解析不准** | 允许人工修正分段；双栏与公式密集页面给出置信度提示；扫描件走 OCR 二期 |
| **数学流式渲染闪烁** | 未闭合不渲染、闭合后替换、缓存；用虚拟终端式的回归测试固定行为 |
| **学术诚信** | 不做“规避 AI 检测”；润色以修订记录呈现；README 与应用内说明“工具辅助，署名与责任在作者” |
| **体积与许可** | KaTeX/pdf.js 的许可证写入 `THIRD_PARTY_NOTICES.md`；模板只收许可证允许分发的；Tectonic 为可选下载 |
| **范围蔓延** | 以 §2 的七个故事为验收线；其余放 §5.8，不抢 M0–M7 |

## 10. 测试与质量

- **纯函数优先**：分段/占位符/对齐/数学分隔符/审稿模板转换都写成纯函数，
  配 `tests/test-*.mjs`，纳入 `npm test`；
- **夹具**：一组小型真实论文（公版或自写）覆盖：双栏 PDF、含公式的 `.tex`、含表格与算法的 `.tex`、
  中英混排 `.md`；
- **Rust**：路径校验、编译日志解析、bib 解析、核验结果合并都有单元测试；
  需要 TeX 引擎的测试在缺引擎时跳过，CI 里设环境变量强制要求；
- **人工验收清单**：每个里程碑写一页，按 §2 的故事逐条走一遍，截图存档；
- **Windows**：GitHub Actions 加 Windows runner，跑编译用例、路径校验、MCP 契约测试；本机没有 Windows 时以 CI 为准；
